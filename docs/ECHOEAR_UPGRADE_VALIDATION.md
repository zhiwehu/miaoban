## 构建结果

- 从公开源码单独构建应用 `2.0.5-voicehub.1`，仅覆盖项目版本和“不刷写资源”选项。
- 使用 ESP-IDF 5.4.0、锁定依赖和已校验提示音。SDK `add_path.sh` 有本地改动，生成标记仍为 `v5.4-dirty`；未声称 SDK 工作区完全干净。记录了源码 / SDK 提交和文件指纹。
- esptool 识别 ESP32-S3 镜像，段校验和及内嵌 SHA256 有效；文件 3,598,096 字节。
- 应用 SHA256：`5ccab7b2d010aefe21a6b97544b7cd032cd8c7597e63d523b440a3d892d44e62`。
- 分区 SHA256：`4811619cacae08ef2e0e71b7220c6033a346ca5da7ca179082408c963ef530b5`，与此前测试设备备份一致。
- 7 项本机已知后台 / MQTT 密码及令牌扫描未命中；未发现已知默认云 OTA 域名。已知值扫描不是全部秘密的证明。
- ZIP 包含应用、清单、使用边界及项目 / 依赖许可；未包含个人 NVS、整机 Flash 或原厂资源。

## 软件验证

- 镜像、分区表和发布门禁校验；硬件记录必须匹配应用 SHA256。
- OTA CRC 与 ESP-IDF 向量一致；异常或待验证的启动记录不盲猜。
- 检查芯片、容量、安全配置、精确分区和现有应用指纹。
- 备份校验、MAC / 分区绑定与恢复范围限制。
- 模拟升级只写非活动应用槽和一个启动选择扇区；读回失败不切换启动。
- 状态改变、错误镜像、未知应用或未验收的版本不得开始写入。
- 模拟恢复能恢复原启动选择，不写 bootloader、分区表或资源区。
- 语音识别与回复须同一轮次；生成回复不等于实际播放，仍需用户确认听见。
- 101 项后端测试及 11 项前端测试通过。浏览器检查候选状态、安装门禁和配网引导，未发起 USB 写入。

## 尚未验收

本轮没有连接 USB 猫头。身份读取、实际备份写入、升级、意外断电、恢复、配网和声学播放仍待实机验证。之前固件的实机记录不能替代这个新版本的验证。

因此 `install.validated=false`，页面显示待实机验收，正式安装按钮关闭。以后需针对同一应用 SHA256 完成身份确认、备份、写入读回、配网、语音回复和恢复验证，再批准普通用户安装。

## 2026-10-27 USB 识别修正

用户连接猫头后，只读 esptool 检测确认芯片 ESP32-S3、Flash 32 MB、PSRAM 16 MB、安全启动和 Flash 加密关闭。原向导错误地要求物理 Flash 恰为 16 MB。现接受 16 / 32 MB 物理容量，但仍要求同一精确 16 MB 分区布局及现有固件指纹；镜像头的 16 MB 配置不代表物理芯片容量。未执行应用升级，正式安装门禁保持关闭。

本次只读活动应用核验通过：版本 2.0.5，SHA256 `d6c6d01af14adc7fe6491bb486a36b8a2914ba4ac3315d930e5ed5838728e7b4`，与升级白名单一致。分区 SHA256 同上。新增物理 32 MB 回归测试通过；浏览器首次复测在应用读取阶段出现通用错误，已补充具体镜像错误提示及控制台诊断。随后浏览器自动化连接中断，尚未完成浏览器全流程复测；不能用 CLI 成功替代网页通过。

## 2026-10-30 USB 校验 / 备份读取中断

用户反馈已识别芯片后，在校验或备份阶段卡住。读取现有 Chrome 接入页发现进度为 55%，控制台记录 `EchoEar operation failed: A No serial data received.`；不能据此认定硬件损坏或确诊线材问题。

检查发现第一步核验现有固件、第二步备份非活动应用都一次调用 esptool-js 读取整个 0x3f0000（约 4 MB）应用槽。当前打包版本的 readFlash 每收到一包都会复制累计缓冲，且设置最多 1024 个包在途；这是浏览器缓冲和长读取的风险，但尚未用实机证明是此次超时的唯一根因。

修正内容：

- 应用核验、备份和写后读回改为每次最多 64 KB，短读立即失败，原有精确分区、镜像校验和与 SHA256 白名单保留。
- Web Serial 接收缓冲增至 1 MB；保持连接时的 115200 波特率，避免 USB 串口在 main 中关闭后重新打开。单个读包无数据超时设为 10 秒，不对未完成的写操作自动重试。
- 具体显示芯片检测、分区检查、启动分区、应用读取 KB 数及指纹校验阶段，统一进度范围为 0–1。
- 错误显示停止阶段及原始错误；未开始刷写的失败释放连接并尝试重启。刷写失败仍保留人工恢复流程，不自动复位。
- 页面说明检查会进入下载模式，期间设备不进行正常联网对话；检查/备份结束后可断开 USB 重启。
- 对新机器分区或现有固件不匹配，明确说明当前升级包不适用，不将其描述为 USB 卡死。此流程仍是已验证来源固件的升级器，不是通用原厂安装器。
