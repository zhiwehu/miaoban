# EchoEar 升级软件验证记录

## 范围

已有兼容 EchoEar ESP32-S3 / 16 MB；浏览器 Web Serial，Flash 读写和备份均在用户电脑。用户明确选择先完成软件部分，暂不连接实机。

## 构建结果

- 从公开源码单独构建应用 `2.0.5-voicehub.1`，仅覆盖项目版本和“不刷写资源”选项。
- 使用 ESP-IDF 5.4.0、锁定依赖和已校验提示音。SDK `add_path.sh` 有本地改动，生成标记仍为 `v5.4-dirty`；未声称 SDK 工作区完全干净。记录了源码 / SDK 提交和文件指纹。
- esptool 识别 ESP32-S3 镜像，段校验和及内嵌 SHA256 有效；文件 3,598,096 字节。
- 应用 SHA256：`5ccab7b2d010aefe21a6b97544b7cd032cd8c7597e63d523b440a3d892d44e62`。
- 分区 SHA256：`4811619cacae08ef2e0e71b7220c6033a346ca5da7ca179082408c963ef530b5`，与此前测试设备备份一致。
- 7 项本机已知后台 / MQTT 密码及令牌扫描未命中；未发现已知默认云 OTA 域名。已知值扫描不是全部秘密的证明。
- ZIP 包含应用、清单、使用边界及项目 / 依赖许可；未包含个人 NVS、整机 Flash 或原厂资源。

## 软件验证

- 镜像、分区表和发布门禁校验；硬件记录必须匹配应用 SHA256。
- OTA CRC 与 ESP-IDF 向量一致；异常或待验证的启动记录不盲猜。
- 检查芯片、容量、安全配置、精确分区和现有应用指纹。
- 备份校验、MAC / 分区绑定与恢复范围限制。
- 模拟升级只写非活动应用槽和一个启动选择扇区；读回失败不切换启动。
- 状态改变、错误镜像、未知应用或未验收的版本不得开始写入。
- 模拟恢复能恢复原启动选择，不写 bootloader、分区表或资源区。
- 语音识别与回复须同一轮次；生成回复不等于实际播放，仍需用户确认听见。
- 101 项后端测试及 11 项前端测试通过。浏览器检查候选状态、安装门禁和配网引导，未发起 USB 写入。

## 尚未验收

本轮没有连接 USB 猫头。身份读取、实际备份写入、升级、意外断电、恢复、配网和声学播放仍待实机验证。之前固件的实机记录不能替代这个新版本的验证。

因此 `install.validated=false`，页面显示待实机验收，正式安装按钮关闭。以后需针对同一应用 SHA256 完成身份确认、备份、写入读回、配网、语音回复和恢复验证，再批准普通用户安装。
