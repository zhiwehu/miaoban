## 本机实机及听感

环境：M4 Max/128GB，ESP32-S3猫头、ESP32-C3底座；相关依赖版本见DEPENDENCIES_TESTED.txt。

- 本地ASR→LLM→TTS完成设备对话；用户确认Qwen+Serena当前可用。
- 修复前观察到约15秒后有文字无声；输出恢复与tts.ready握手部署后，用户复听反馈有声。
  一次两轮回传40/70个音频包，解码和播放计数全部增长，状态丢包为0。
- 后端空闲30秒同步到旧设备：通过关闭对话连接让猫头回Idle、恢复唤醒。自动化用例通过，
  不能冒称所有真实待机循环都已完整验收。
- 待机听声转头已运行；曾收到底座STALL=2，重新上电后故障=0，用户确认恢复。
- 唤醒后聆听的转头一致性仍待排查。

## 性能观测

一次较低负载单句Qwen合成：3.36秒音频/2.05秒生成，首包约522ms，RTF=0.61。
另一次并行负载下相近长度语音生成约10秒。不是受控A/B或跨硬件性能保证。
TTS首包不是用户说完到机器人出声的总延迟。

一次已配置的LLM→Qwen→16k→Opus→WebSocket测试：约4.5秒音频、75包，最大包间隔
91.7ms，模拟接收缓冲断粮0次；这是软件接收模拟，不是外部麦克风的物理测量。

## 尚未验证或未实现

- 真实外放AEC和自然插话成功率、物理停声P95；当前ESP32不自动声明AEC。
- 唤醒后持续跟随的完整状态矩阵、不同距离/方位的定位准确率。
- 连续2小时和多实际设备的稳定性；其他Mac规格的最低配置。
- 手机App成品、端到端语音模型、已有Grok Bot的专有会话接入。
- 猫头源码与历史上游 Git 提交的精确补丁关系；原工程无 Git 元数据。
- 逐家云API兼容性。

真实对话状态“generated”不能改写成“用户已听到”；ready/stopped也不是物理扬声器测音。
