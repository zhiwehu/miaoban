# USB 一体化接入

在运行 VoiceHub 的电脑上，用 Chrome / Edge 打开 http://127.0.0.1:8765/#connections 。准备电脑、兼容 EchoEar 猫头和 USB 数据线即可，电脑保持连接目标网络。

1. 选择 EchoEar，插入猫头 USB，点击“连接并检查设备”，在浏览器弹窗选择猫头。
2. 检查通过后填写 2.4 GHz Wi-Fi 名称与密码，点击“保存原机备份并连接”，选择备份保存位置。
3. 页面自动准备带令牌的设备专用监听，读取完整原机 Flash（16 / 32 MB）、保存 `.vhdevice` 文件并重新打开校验；备份较大，按页面的 MB 进度等待。
4. 已有兼容固件直接继续配网。若“同时更新到已验证的适配固件”可选，可勾选让本次流程先更新固件；未完成实机验收的候选版本继续禁止安装。
5. 自动写入 Wi-Fi 和本机 VoiceHub 连接信息，并读回核对、重启。等待上线，唤醒并说“你好”，听到回复后点击确认。

Wi-Fi 密码由浏览器经 USB 处理，不上传 VoiceHub 后端或外部服务，也不存入浏览器持久存储。备份文件包含原固件、原网络凭据和设备设置，请保存在自己的电脑。连接信息中的令牌由程序填写，不需要手工复制 OTA URL。

电脑有多块无法自动确定的网卡时，页面会显示网络选择框；选择与喵伴 Wi-Fi 可互通的网卡后重试。网络设置写入成功与设备上线分别显示。超过两分钟未上线时，检查 SSID、密码和 Wi-Fi 客户端隔离；同一个 Wi-Fi 名称不保证两台设备能互相访问。

## 升级与恢复

普通接入仍检查芯片、安全配置、准确分区与现有固件指纹。未知设备、加密 NVS、损坏配置或空间不足会停止；不会清空 NVS 或强刷应用。新的网络配置会替换已记住的 Wi-Fi 列表和旧连接入口，保留音量等其他设置；原值在备份中。

完整原机备份使用 `.vhdevice`。原有 `.vhbackup` 是旧版升级备份，仅含被覆盖的非活动应用、NVS 和启动记录，两者恢复入口均保留。

恢复时先连接 USB 检查；如果当前应用或 OTA 损坏，但芯片、安全状态和分区通过检查，页面会进入“仅可恢复”状态。展开“固件升级与备份恢复”，选择同一设备的备份并点击恢复。完整备份恢复应用槽、NVS 和启动记录，启动记录最后写；不写引导程序、分区表或资源区。备份仍保有完整原始 Flash，可供后续专门恢复使用。

## MCP 配置位置

“模型与语音”只操作模型、音频、唤醒、提示词和记录保留，不再读取或提交 MCP 设置。天气默认城市、新闻来源和数量位于各工具卡的“配置与测试”；规划方式和通用超时位于 MCP 页的“工具通用设置”。保存后按页面提示重新连接客户端生效。

## 浏览器提示来源地址校验失败

部分本机浏览器或代理环境会将 Origin 的端口省略。2026-10-30 在实际 Chrome 中复现：页面是 `http://127.0.0.1:8765`，请求 Origin 却为 `http://127.0.0.1`，且 Fetch Metadata 标记为 same-origin。现仅对本机回环访问、协议和主机完全相同、缺省端口且浏览器声明 same-origin 的情况兼容；其他端口、外部主机、不同协议、null 和缺失元数据仍拒绝。

连接准备的非 JSON 错误响应会显示可读提示，不再以 Unexpected token 覆盖真实错误。这个阶段失败时尚未开始读取原机备份或写入设备，修复后刷新页面，重新连接检查设备即可重试。
