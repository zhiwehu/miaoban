# MCP 调用展示与工具目录

对话记录与网页聊天在对应轮次中显示 MCP 调用卡片。包括工具名称、状态、实际参数、
决策方式、耗时及错误原因；运行中的耗时按客户端时钟估计，结束耗时使用服务器记录。
调用卡片可展开，参数通过 textContent 渲染，不解释成 HTML。工具结果由助手回复呈现。

状态为执行中、成功、失败、取消、状态未确认。打断只取消仍在执行的卡片，不把已完成
查询改成取消；只有开始记录而没有结束证据的历史调用显示“状态未确认”。普通聊天不展示调用。
实时事件可能同时由管理流和客户端流送达，按时间/序号归并，避免重复卡片。

## 管理接口

沿用现有管理员认证、同源限制；设备监听不提供管理接口。

- `GET /api/mcp`：`servers`、`tools`、`planner`、`external_import_supported`。
  每个 tool 含 MCP 原生 name/description/inputSchema/annotations、server_id、enabled。
  server 的 startup=on_demand 表示注册且按需启动，不表示已测量上游网络可用性。
- `GET /api/sessions/{sid}/tool-calls?turn_id=...`：返回 `events` 和 `active_turn_id`。
  turn_id 可重复指定，最多 100 个不同值，省略时使用最近 100 条消息的轮次。
  只返回该会话和指定轮次的调用、结束、错误、中断证据，最多 600 条，按事件 ID 升序。
  参数形式与原日志一致；不包含音频、管理令牌或模型服务密钥。
- 工具启停沿用 `PUT /api/config`：先读取新配置，仅修改所选工具开关，串行保存，
  不覆盖用户未提交的模型表单；设置仍对新连接生效。

目录展示三个内置工具，包含参数、启用状态、调用示例和当前决策方式。默认参数入口
跳转现有模型与语音设置，不再创建一份重复配置。

## 用户扩展的边界

本次不开放上传代码、自动安装依赖或任意服务连接。后续可以增加“导入 MCP 服务配置”流程：
校验配置 → 在明确的权限/运行环境下连接 → initialize/tools/list → 校验 Schema → 用户启用。
凭证单独存储，导入包不可包含自执行安装脚本；失败可禁用或移除。

原生 MCP 工具发现并不等于 Rex 能识别新工具。当前 adapter 的分类标签和抽取字段固定；
新工具必须增加训练样本/字段并重训，或引入经评估的动态候选决策方式。仅上传配置无法完成这一步。

验收覆盖：目录和开关持久化；实时执行/成功/失败/取消；历史刷新恢复；跨会话隔离、
大量状态日志不淹没调用证据；错误/空/加载状态；320/768/1024/1440 宽度及浏览器异常检查。
