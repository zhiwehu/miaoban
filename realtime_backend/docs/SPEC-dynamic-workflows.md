# 动态任务链与独立邮件 MCP

目标：从自然语言生成有界工具计划，支持步骤结果引用、缺参追问、顺序执行、语音/页面确认、取消和可见状态。不是固定document_email模板，不提供任意代码或桌面操作。先支持已有启用的MCP、文本编写、TXT/Markdown/CSV/基础DOCX生成、联系人解析、邮件草稿与SMTP发送。

边界：规划器只能输出注册工具及Schema参数，最多8步；程序校验DAG、引用字段/类型、大小、工具开关和权限。外部结果仅为数据。文件输出只能在受控artifact目录，使用artifact_id，拒绝模型路径；邮件附件仅接受本次任务生成/引用的artifact。缺工具/不明确时追问，不编造成功。

邮件作为独立stdio MCP（python -m voicehub.email_mcp），提供email_prepare/email_status/email_send。SMTP主机/端口/SSL或STARTTLS/账号/授权码单独配置，凭据不进模型或参数，API不回填密码。草稿可在未配置SMTP时准备，发送暂停到待配置。发送必须持有由平台根据当前会话与草稿/附件/SMTP配置摘要生成的一次性授权，模型无法自行签发。

确认是执行器控制状态，不是LLM参数：发送摘要含收件人/发件人/主题/正文/附件，10分钟过期，草稿或配置变更失效。只接受同一会话明确“确认发送”，不接受“是的”或引用/否定句。发送前持久化sending状态和Message-ID；不自动重试邮件，超时/崩溃/取消后结果不明须标记unknown防重复。成功仅表示SMTP接受，不保证收件人收到/阅读。开发只发往本地测试SMTP。

模块依赖：plan（结构与引用）→artifacts/mail（独立能力）→manager（状态机/调用/授权）→chat/UI/API。任务与草稿保存在0700运行目录、文件0600，不随源码发布。页面提供任务目标输入、步骤状态、文件下载、确认/取消/继续和SMTP设置；语音调用前先回应并排空提示音。

管理员API /api/workflows、/api/workflows/{id}、/api/workflows/{id}/actions，/api/workflow-settings，/api/artifacts/{id}。会话绑定voice，网页操作admin授权。只显示有限最近记录，保存任务进度，重启不自动重放副作用。第一版顺序调度、失败明确停下，用户显式继续；不宣称任意复杂任务均可靠。

验收：计划引用/类型/循环/非法工具拒绝；真实文件生成和摘要绑定；SMTP凭据隔离、一次性票据、过期/修改/跨会话/重复发送拒绝；本地SMTP链路；动态不同顺序与不同工具组合；4B真实模型规划；语音确认和页面完整状态；旧功能回归。命令python -m unittest discover -s tests -q；node --test tests/test_mcp_calls.mjs。

## 本地 4B 规划约束

模型每轮只选择下一个工具和参数；主机分配 step1 等标识，并列出可引用的输出。模型输出 `$step1.artifact_id` 这类变量，由主机转为显式引用。每步校验后加入暂存计划，重复步骤拒绝并反馈模型修正；收到 done 后才校验并执行完整计划。单次规划最多 8 步、90 秒，失败时停下追问。工具发送权限由主机掌握。小模型仍可能规划不正确，必须核对文件和邮件草稿。
