# 本地音乐与用户 MCP 扩展

沿用管理员认证、同源校验和事件卡片。音乐目录由管理员配置，不由模型传入；路径、播放
进程状态不作为工具参数暴露。搜索返回不透明 track_id、标题及有限结果，播放仅允许目录内文件。
Mac 使用 afplay 输出至后端电脑默认音频设备，暂停/继续/停止仅操作核验身份的本项目播放进程。
这不等于将音乐音频流发送给 ESP32。扫描有文件数上限，拒绝越界路径和目录外符号链接。

用户扩展支持：标准 JSON 中的单个 mcpServers stdio 配置，或 ZIP 根目录 mcp.json 加 Python 服务。
上传只保存和静态检查，不执行。启用需显式确认“以当前用户权限运行代码”，随后执行真实 MCP
initialize/tools/list 并校验工具 schema；成功后才允许调用。无法提供 OS 沙箱隔离，不宣称安全沙箱。
不自动安装依赖。ZIP 限大小、文件数、类型，拒绝穿越/绝对路径/符号链接和重复路径。
进程以参数数组启动，不经 shell；只继承必要环境和用户明确配置的环境值。禁用/删除后不允许调用。

外部工具名加服务命名空间，不能覆盖内置工具。调用时复核发现结果和参数，限制启动/执行超时及输出，
取消时清理进程。schema 与返回内容只作数据，不拼接代码或 HTML。服务配置/代码仅保存在 data/ 中。

GET /api/mcp 返回注册工具、启用状态、扩展服务及能力；POST /api/mcp/import 上传 JSON/ZIP；
POST /api/mcp/servers/{id}/enable 校验 trust=true 后启用验证；disable/delete 关闭或移除服务；
POST /api/mcp/tools/{name}/test 执行显式手动参数测试。每个入口独立限制请求大小。

音乐配置 tools.music、tools.music_directory；旧配置迁移补默认关闭与空目录。新连接生效。
Rex 未训练音乐/任意外部工具，明确音乐操作由约束解析生成参数；外部工具先通过动态目录 LLM 独立判断，未选中时再交给原 Rex；音乐等新增工具采用
约束解析或动态目录 LLM 规划，UI/日志记录实际决策来源。不把“已导入”当成“已验证可用”。

验收：目录与文件边界、进程身份和状态；真实 stdio 音乐搜索；上传未执行、未授权启用拒绝、
恶意 ZIP/schema/超时、发现与参数校验、禁用删除、上传示例端到端调用、对话分发与卡片、浏览器界面。
