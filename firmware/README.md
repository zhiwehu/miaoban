# 猫头与底座固件

## 源码与支持范围

- `head/`：猫头完整 ESP-IDF 源码工程，含核心、EchoEar/common 板级实现、依赖锁、
  16MB 分区和已使用的配置快照。只支持本次 EchoEar ESP32-S3 目标。
- `base_controller/`：ESP32-C3 底座控制器源码。
- `shared/`：两端的串口帧协议。

猫头基于小智／喵伴既有工程，来源、许可和源码快照边界见 ../THIRD_PARTY_NOTICES.md。
源码齐全不表示包含整机 Flash、模型权重、原厂表情、唤醒资源或 NVS。

## 猫头构建（不连接设备）

安装并启用 ESP-IDF **5.4.0** 的环境，保留 head 和 shared 的相对目录：

```sh
cd firmware/head
python3 scripts/prepare_sounds.py
idf.py build
```

首次配置由 sdkconfig.defaults 选择 esp32s3/EchoEar、16MB 分区和中文。
提示音脚本从固定的小智上游提交下载 common/zh-CN 声音并核对 SHA256。
其余组件按 dependencies.lock 下载到 managed_components，需网络和磁盘空间。
发布验证使用新的构建目录和已有的锁定组件缓存；不是另一台空白电脑的安装验证。

CONFIG_OTA_URL 默认留空，请通过 menuconfig 设置自己的私有后端 OTA 配置入口。
设备还需要在 NVS 中配置自己的 WebSocket 地址与令牌，详见根 README 的设备接入。
公开代码保留原协议的其他接入能力，显式设置云服务后仍可能访问云；检查自己的配置。

默认构建可生成通用资源，但不保证包含现有“小宝同学”唤醒词或原厂眼睛动画。
不附送原厂资源，也不建议将默认生成资源直接覆盖到已正常运行的猫头。
`idf.py flash` 可能同时写 bootloader、分区、应用与资源；本说明不把它当应用升级命令。

## 猫头主要修改

- 本地 WebSocket 配置优先，移除缓存 MQTT 的隐式云端回退。
- 在 Speaking 状态、解码器与输出就绪后按 turn_id 回传 tts.ready。
- 刷新输出活动时间并与 15 秒断电定时器串行化，增加解码/播放计数。
- 唯一 I2S 读取及原始双麦 observer，供方向估计复用。
- DOA、人声门槛、稳定证据与位置反馈门控；播报时抑制跟随，保留运动保护。

## 底座构建

```sh
cd firmware/base_controller
idf.py set-target esp32c3
idf.py build
```

构建不是刷写。源码的GPIO映射只针对已检查的这台底座：PWM为GPIO4/10，使能为GPIO5，
UART TX21/RX20，角度反馈为ADC通道0。其他硬件、驱动板和修订不能直接套用。
板子上电可能主动回中，实物调试前先确认转轴、电线和运动空间。

控制目标区间77..247是本设备的标定控制值，不是对任意底座的物理行程保证。
故障0=正常、1=角度传感异常、2=STALL、3=动作超时；故障时禁止不断自动重试。
检查原因后再恢复供电，不能为“转起来”删除保护。方向正负与中位值需要实物标定。

## 刷写与配置边界

先按芯片/MAC确认猫头与底座，备份对应设备现有应用、分区与NVS，再核对活动OTA槽。
本项目实机改动只更新目标应用分区，并核对配置和资源抽样未变化；不能把这个事实推广为
其他分区布局也能使用同一偏移。不要整片擦除或复用别人的NVS、Wi-Fi、令牌和原厂资源。

设备的本地WebSocket地址和私有OTA配置地址必须设置为你自己的后端；后端将生成设备
令牌。模型推理本地化不自动保证固件所有版本发现请求都已经离线，需检查实际OTA配置。

## 实机现状

待机听声跟随和故障回传已实际运行；STALL后经检查并重新上电，用户确认恢复转头。
用户还报告过唤醒后聆听不跟随，未做完对比验收。仅从源码包含Idle/Listening条件，不能
推断两种状态下的实际采音、VAD、方向队列和电机表现一致。此项仍为已知待查问题。
